# Global Futures Terminal (fixed)

`flutter pub get` 후 `flutter run`으로 실행합니다. (Flutter SDK 필요, 이 세션에서는 빌드 검증을 하지 못했습니다.)

## 원본 대비 수정 사항

1. **`setState` after dispose 방지** — `_verifyInitialLicense()`가 비동기 완료 후 `mounted` 체크 없이 `setState`를 호출하던 문제를 수정.
2. **거래소 선택이 실제로 작동하도록 수정** — 기존에는 Bybit/Bitget/OKX/Gate.io를 선택해도 항상 바이낸스 웹소켓에만 연결되던 버그. `_wsConfigFor()`에서 5개 거래소 각각의 엔드포인트/구독 메시지/응답 파서를 구현해 실제로 해당 거래소 시세를 받아오도록 함.
3. **"충전하기" 버튼의 무결제 크레딧 지급 제거** — 실제 결제(IAP/USDT 결제) 연동 없이 버튼 클릭만으로 크레딧이 늘어나던 로직을 제거하고 "결제 연동 준비 중" 안내로 대체. 실제 서비스에서는 결제 게이트웨이 콜백에서 서버가 검증한 뒤에만 크레딧을 지급해야 함.
4. **죽은 코드 정리** — `kCostFloorMarginRatio`가 선언만 되고 쓰이지 않던 것을 실제 크레딧 원가 계산에 사용하도록 연결(`kProActionCreditCost = 원가 / (1 - 마진율)`).

## 남은 구조적 한계 (코드 수정만으로는 해결 불가)

- **`AntiTamperLicenseVault`는 서버 검증이 없는 로컬 전용 로직**입니다. 라이선스 키·salt가 클라이언트 바이너리에 그대로 노출되고, "trust-on-first-use" 방식이라 최초 실행 시 16자 이상 아무 문자열이나 통과됩니다. 실제 크랙 방어가 필요하면 라이선스 발급/검증을 백엔드 API로 옮기고 앱은 서버가 내려준 단기 토큰만 들고 있어야 합니다.
- **`_executeSecureOrder`는 실제 거래소 주문 API를 호출하지 않습니다.** 크레딧을 차감하고 성공 메시지만 보여주는 프로토타입 단계입니다. 실거래 연동 시 각 거래소의 인증된 REST/WS 주문 API 연동이 별도로 필요합니다.
- 거래소별 웹소켓 응답 필드명은 거래소가 API 스펙을 바꾸면 달라질 수 있어 실기기/네트워크 환경에서 검증이 필요합니다 (이 세션은 아웃바운드 wss 연결을 확인할 수 없었습니다).
